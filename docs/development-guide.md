# Development guide

Day-to-day workflow: just targets, the devcontainer, tests and linting, environment variables, and how the backend and frontend are laid out.

## Toolchain

Python 3.13 with [uv](https://docs.astral.sh/uv/) (`pyproject.toml` + `uv.lock`) for the backend, Node with npm for the frontend (`frontend/package.json`). You rarely need either on the host: every command runs inside Docker Compose. The `justfile` exports `COMPOSE_FILE=docker-compose.local.yml`, so `just` targets always hit the local stack. Plain `docker compose` commands need the same file (`-f docker-compose.local.yml` or `COMPOSE_FILE`); the compose project is named `llmlab`, so containers are `llmlab-<service>-1`.

## just targets

| Target | What it does |
| --- | --- |
| `just bootstrap` | Create `.envs/.local/.django` and `.postgres` from the templates, generate credentials |
| `just build [args]` | `docker compose build` |
| `just up` / `just down` | Start (`up -d --remove-orphans`) / stop the stack |
| `just prune [args]` | `docker compose down -v`: removes containers **and volumes** (database, apps-dind images, certs) |
| `just logs [service]` | Follow container logs |
| `just test [args]` | `docker compose run --rm django pytest`, the same command as CI |
| `just manage <args>` | Run any `manage.py` command in a one-off django container |
| `just frontend-install` | `npm install` inside the frontend container |
| `just frontend-dev` | Run the frontend service in the foreground |
| `just frontend-build` | Production frontend build (`npm run build`) |

`docker compose exec django python manage.py ...` does **not** work: `DATABASE_URL` is built by the image's `/entrypoint` from the `POSTGRES_*` variables, and `exec` skips it. Use `just manage`, or prefix the command: `docker compose exec django /entrypoint python manage.py <cmd>`.

## Reload behaviour

| Service | Picks up code changes | Notes |
| --- | --- | --- |
| `django` | `uvicorn --reload` | A reload kills threads running in it: interactive analysis runs, workspace provisioning, tool installs, report generation, container actions |
| `executor` | No | Restart it after backend edits; drain first so running jobs are not interrupted ([Execution engine](/docs/EXECUTION)). The UI flags it as running older code |
| `celeryworker`, `celerybeat`, `flower` | `watchfiles` restarts them on `.py` changes | |
| `frontend` | Vite HMR | |

The scripts baked into the image (`/start`, `/start-celeryworker`, ...) change only after `just build`. The executor is the exception: locally it runs `compose/local/django/start-executor` from the bind-mounted repo.

## Devcontainer

`.devcontainer/devcontainer.json` attaches VS Code to the `django` service, layering `.devcontainer/docker-compose.devcontainer.yml` (a `dev-user` venv, caches, `DOCKER_HOST=tcp://apps-dind:2376` for the `docker` CLI) and a gitignored, host-specific `.devcontainer/docker-compose.host.yml` on top of the local compose file. In the devcontainer the django command is overridden: `post-attach.sh` starts `/entrypoint /start` in the background on attach and logs to `/tmp/django-start.log`, so the API (and the migrate step) only come up once an editor attaches. The git pre-commit hook uses the devcontainer's venv, so commit from inside it.

## Environment files

Each service reads `.envs/.local/.django` and `.envs/.local/.postgres` (`POSTGRES_HOST`, `POSTGRES_PORT`, `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`). Variables in the template:

| Variable | Purpose |
| --- | --- |
| `DJANGO_DOMAIN` | Default sender domain, OpenRouter `HTTP-Referer`, bootstrap admin email domain, `APPS_DOMAIN` default |
| `REDIS_URL` | Celery broker and result backend, realtime pub/sub, executor doorbell |
| `CELERY_FLOWER_USER` / `CELERY_FLOWER_PASSWORD` | Flower login (generated by bootstrap) |
| `OPENROUTER_API_KEY` | Optional global fallback key for users without a personal key |
| `OPENROUTER_ALLOW_GLOBAL_KEY_FALLBACK` | `False` forces every user to bring their own key (default `True`) |
| `FRONTEND_PUBLIC_ORIGIN` | The URL users open in the browser; used in verification and reset emails |
| `APPS_DOMAIN`, `APPS_SUBDOMAIN_PROXY`, `APPS_PUBLIC_ORIGIN` | How browsers reach generated apps ([Deployment guide](/docs/deployment-guide#sample-app-routing)) |
| `DJANGO_ALLOWED_HOSTS`, `CORS_ALLOWED_ORIGINS`, `CSRF_TRUSTED_ORIGINS` | Set all three when serving from anything other than localhost |

Other settings read from the environment, with their defaults (`config/settings/base.py`, `local.py`):

| Variable | Default | Purpose |
| --- | --- | --- |
| `ACCOUNT_EMAIL_VERIFICATION` | `optional` (local), `mandatory` (production) | allauth email verification |
| `DJANGO_ACCOUNT_ALLOW_REGISTRATION` | `True` | Allow self sign-up |
| `GENERATION_DEFAULT_STACK` | `flask-react` | Stack used when neither the request nor its profile names one |
| `AGENT_DEFAULT_HARNESS` | `opencode` | Harness for agent runs (`opencode`, `mini-swe-agent`, `aider`) |
| `AGENT_MAX_LLM_REQUESTS`, `AGENT_WALL_CLOCK_SECONDS`, `AGENT_MAX_TOTAL_TOKENS`, `AGENT_MAX_COST_USD` | `100`, `3600`, `30000000`, `5.0` | Per-run agent budgets (experiments and jobs may override) |
| `AGENT_MAX_CONCURRENT_RUNS` | `1` | Initial executor sandbox slots (editable at runtime by staff) |
| `AGENT_SANDBOX_MEM_LIMIT`, `AGENT_SANDBOX_NANO_CPUS` | `3g`, `2000000000` | Per-sandbox caps, frozen into job snapshots |
| `AGENT_AUTO_EVALUATE` | `True` | Grade every agent sample with the hidden conformance suite |
| `AGENT_NETWORK_POLICY`, `AGENT_SAMPLING_POLICY` | `packages`, `provider_default` | Sandbox egress and sampling defaults |
| `EXECUTOR_TICK_SECONDS`, `EXECUTOR_LEASE_SECONDS`, `EXECUTOR_HEARTBEAT_SECONDS` | `2.0`, `90`, `20` | Executor loop timing |
| `APPS_DIND_MEM_LIMIT`, `APPS_DIND_APP_RESERVE` | `4g`, `1g` | Memory rule for executor slots; keep the first equal to apps-dind's `mem_limit` |
| `ANALYSIS_MAX_WORKERS` | `4` | Analyzer tools run in parallel per analysis run |
| `LLM_LOCAL_AGENT_RUNS` | on when `APPS_DOCKER_HOST` is set | Allow agent runs on local (non-OpenRouter) endpoints |
| `INFERENCE_DIRECT_ALLOWED_TARGETS`, `INFERENCE_HOST_PUBLIC_IPS`, `INFERENCE_EXTRA_BLOCKED_CIDRS` | empty | Direct-endpoint allow and block lists ([Local models](/docs/LOCAL_MODELS)) |
| `LLMLAB_PUBLIC_URL` | request host | Base URL the relay install commands point at |
| `TRUSTED_PROXY_CIDRS` | empty | Proxies whose `X-Forwarded-For` hop is trusted for relay client IPs |
| `STACK_REQUIRE_APPROVAL` | `False` | Non-staff stacks need staff approval |
| `STACK_ALLOWED_PYTHON_IMAGES`, `STACK_ALLOWED_NODE_IMAGES` | `python:3.11-slim,python:3.12-slim`, `node:20-alpine,node:22-alpine` | Base-image allowlist for user stacks |

The compose file sets the apps daemon wiring itself (`APPS_DOCKER_HOST=tcp://apps-dind:2376`, `APPS_DOCKER_CERT_PATH`, `APPS_UPSTREAM_HOST=apps-dind`, `APPS_PROXY_PATH=True`) and the executor's LLM proxy (`LLM_PROXY_BIND`, `LLM_PROXY_UPSTREAM`). It interpolates these from your shell or a root `.env` file:

| Variable | Default | Used for |
| --- | --- | --- |
| `APPS_DIND_MEM_LIMIT`, `APPS_DIND_CPUS` | `4g`, `4` | apps-dind caps (also passed to django and executor) |
| `LLMPROXY_SUBNET`, `LLM_PROXY_ADDR`, `APPS_DIND_LLMPROXY_ADDR` | `172.30.99.0/29`, `172.30.99.2`, `172.30.99.3` | Internal `llmproxy` network; change together |
| `LLM_GATEWAY_EGRESS_SUBNET` | `10.213.0.0/24` | Nested network of local-model gateways inside apps-dind |
| `FRONTEND_ORIGIN` | `http://localhost:8000` | Passed to the frontend container as `ORIGIN` |
| `TRUSTED_PROXY_CIDRS` | empty | Passed through to django |

## Backend layout

Django 6 project with django-ninja. Settings live in `config/settings/{base,local,production,test}.py`, the API root and router mounts in `config/api.py`, plain Django views (SSE stream, relay protocol, MCP endpoint, `/apps/` proxy) in `config/urls.py`. Eighteen apps under `backend/`:

| App | Responsibility |
| --- | --- |
| `users`, `tokens`, `credentials` | Accounts (allauth headless + MFA, bootstrap admin), Bearer API tokens, encrypted per-user provider keys |
| `llm_models` | Model catalog synced from OpenRouter, models.dev / Hugging Face enrichment |
| `generation` | Generation jobs (agent, scaffolding, custom), experiments with schedules and post-runs, run presets, app specs, prompts, blocks, profiles, evaluation |
| `execution` | The executor process: leader lock, scheduler, lanes and slots, leases, reconciler |
| `inference` | LLM endpoints (OpenRouter, relay, direct), LLM request queue, the executor's internal LLM proxy, relay protocol |
| `analysis` | Analyzer workspaces, tool catalog, analysis runs, findings, AI review |
| `runtime` | Stacks, builds and runs generated apps as containers, app routing and proxying |
| `statistics`, `rankings`, `reports` | Aggregation and study tables, model scoring, saved and study reports |
| `integrations` | MCP server, cloud LLM providers, GitHub export, outbound webhooks |
| `realtime` | Server-sent events stream over Redis pub/sub |
| `export` | CSV/JSON/SARIF downloads, review samples |
| `docs`, `system` | This docs viewer; staff-only system snapshots and maintenance |
| `automation` | Legacy pipelines and batches; kept for existing data, its router is unmounted |

Shared helpers live in `backend/common/` (exceptions, `dispatch_in_thread`). The relay client that connects a GPU box to an instance is in `relay/` at the repo root.

Apps follow one convention: `models.py`, `api/{views,schema}.py`, `services/`, `tasks.py` (where there are Celery tasks), `tests/`. Views raise ninja's `HttpError`; services stay free of ninja imports and raise `backend.common.exceptions.*`, which an exception handler in `config/api.py` maps to HTTP responses.

Scoring constants live in one place: `backend/rankings/services/constants.py` defines `SEVERITY_WEIGHTS` (shared by rankings, statistics and the report generators) and the `SEVERITY_WEIGHT_SCHEMES` used by the sensitivity analysis. Change them there, nowhere else. The methodology is described in [Architecture](/docs/ARCHITECTURE).

### Seed data and management commands

Seeds sync after every `migrate` through `post_migrate` handlers; a seeding error is logged, never raised. Data files: `backend/analysis/data/tools/*.yaml` (tool catalog), `backend/generation/data/` (library), `backend/runtime/scaffolding/` (stacks).

| Command | Purpose |
| --- | --- |
| `seed_analysis_tools`, `seed_generation_templates` | Re-run a seeder by hand |
| `lint_generation_data` | Validate the generation library data files |
| `enrich_models` | Attach models.dev / Hugging Face metadata to the catalog |
| `seed_benchmarks` | Load benchmark results from a JSON fixture |
| `run_executor`, `executor drain\|resume\|status`, `wait_for_migrations` | Executor process and control ([Execution engine](/docs/EXECUTION)) |
| `sync_container_status`, `reconcile_app_routes` | Reconcile container rows with Docker; rewrite Traefik route files |
| `export_study_tables`, `healing_ablation`, `study_report` | Study outputs ([Study tables](/docs/STUDY_TABLES)) |
| `export_review_sample`, `score_review_sample` | Human review sample export and scoring |
| `runautomationscheduler` | Legacy automation scheduler loop; nothing creates pipeline schedules any more |

## Frontend layout

SvelteKit 2 with Svelte 5 runes, Tailwind 4 and adapter-node, in `frontend/`. App routes live under `src/routes/(app)/` (one directory per feature: `experiments`, `sample-generator`, `applications`, `analysis`, `analyzers`, `endpoints`, `models`, `templates`, `runtime`, `rankings`, `statistics`, `reports`, `docs`, `system`, `users`, ...), auth pages under `src/routes/(auth)/auth/`. Old URLs such as `/automation`, `/integrations` and `/settings` are redirects. API clients are in `src/lib/api/`, navigation in `src/lib/nav.ts`, settings sections in `src/lib/settings-sections.ts`. UI conventions are in `frontend/DESIGN_SYSTEM.md`.

In the local stack the Vite dev server on :8000 proxies `/api`, `/_allauth`, `/admin`, `/media` and `/apps` to django via `API_TARGET=http://django:8000`. Always develop against http://localhost:8000, not :8001.

## Testing

```bash
just test                        # whole backend suite
just test backend/analysis       # one app
just test -k workspace -x        # any pytest args pass through
```

pytest runs with `--ds=config.settings.test --reuse-db --import-mode=importlib` (`pyproject.toml`). Add `--create-db` after changing seed data (for example the analyzer tool YAML), since the reused test DB keeps the old rows. Two suites running at once share the test database; give one its own with `docker compose run --rm -e POSTGRES_DB=llmlab_<name> django pytest`. Shared fixtures live in `backend/conftest.py`; factories in `backend/<app>/tests/factories.py` (analysis, automation, generation, llm_models, runtime, users).

Frontend unit tests use vitest: `npm test` in `frontend/`. Type checking is `npm run check` (`svelte-check`). The frontend container is capped at 2 GB and can be OOM-killed by `svelte-check` or `vite build`; run them with a larger heap on the host if that happens.

## Linting and CI

`.pre-commit-config.yaml` runs generic file hooks, django-upgrade (target 6.0), ruff check and ruff format, pyproject-fmt, djLint, prettier on `frontend/`, and gitleaks. It skips `docs/` and migrations.

| Workflow | Jobs |
| --- | --- |
| `ci.yml` | pre-commit; mypy on `backend` (non-blocking); backend tests (bootstrap, `makemigrations --check`, migrate, pytest in the local compose stack); frontend (`npm ci`, `svelte-check` non-blocking, `npm test`, `npm run build`, Node 24) |
| `codeql.yml` | CodeQL for Python and JavaScript/TypeScript |
| `gitleaks.yml` | Secret scan of the full history |
| `trivy.yml` | Trivy filesystem and image scans (HIGH/CRITICAL) when compose files, Dockerfiles or dependency locks change, plus weekly |

## Working on these docs

The in-app viewer at `/docs` serves raw Markdown straight from the repo's `docs/` directory; there is no build step. Rules, enforced by `backend/docs/services.py` and the client renderer:

- Exactly one `# H1` as the first line; it becomes the page title. The first plain paragraph after it becomes the landing-card blurb.
- No YAML frontmatter (it would render as content). No images (nothing serves them).
- Cross-link other pages as absolute `/docs/<slug>` paths; relative `.md` links do not resolve in the app.
- Mermaid fences and `> [!NOTE]` / `> [!WARNING]` alerts are supported; code fences highlight for the common languages.
- New files land in the "Other" category unless you add their slug to `CATEGORY_MAP` in `backend/docs/services.py`.
