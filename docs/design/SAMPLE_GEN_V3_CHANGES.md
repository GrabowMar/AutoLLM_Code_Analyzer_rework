**Identity (`identity.py`)**
- `canonical_json` NFC/LF-normalizes dict **keys** as well as values and rejects keys that collide after normalization. Anything that is not a JSON scalar, list, tuple or dict is rejected (`CanonicalJSONError`), including pydantic models (dump them with `model_dump(mode="json")` first), sets, bytes and `Decimal`. `1` and `1.0` hash differently.
- `tree_hash` rejects absolute paths, backslashes, empty/`.`/`..` segments, duplicate paths and non-lowercase-hex shas.
- `condition_hash(levels)` hashes sorted `[factor_key, level]` pairs, not bare levels: enum levels (`stub`, `true`) are not self-describing.
- `plan_hash` sorts the cell rows; `conditions` (condition hashes) and `units` (unit keys) keep index order, because cells refer to them by index.
- Every hash of section 3.1 lives in `identity.py`: `library_content_hash`, `task_structured_hash`, `task_prose_hashes`, `condition_hash`, `design_hash`, `plan_hash`, `prereg_hash`, `target_hash` and `crn_seed` (section 9.4), next to `compute_keys`. `normalized_sha` is `text_sha(<normalizer output>)` and stays with WP-13.

**Validation mechanics (`models/base.py`)**
- `ValidatedModel.CONTRACT_FIELDS = {field: Contract(schema)}` is checked by `full_clean()` (inside `clean_fields`) **and** by `save()`; `save(update_fields=...)` checks only the listed fields. `None` is skipped for nullable JSON columns. `QuerySet.update()`, `bulk_create()` and raw SQL bypass it; the key invariants are also database check constraints.
- `derive_fields()` fills derived columns before validation and before every save: an empty column is filled, a supplied value that differs is a `ValidationError` (never silently overwritten). `DERIVED_FROM` extends `update_fields` so `save(update_fields=["design"])` also writes `design_hash` and the mirrored columns.
- Frozen rows raise `ImmutableVersionError`, an `APIError` with status 409 (`backend.common.exceptions`), so a view that lets it escape answers 409. `VersionedQuerySet.update()` refuses immutable columns too.
- The module is `models/base.py`, not `_base.py`: migration 0024 references `backend.generation.models.base.validate_rel_path`.
